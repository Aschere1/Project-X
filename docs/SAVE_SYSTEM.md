# 普通时间线存档模块

## 当前功能

- K：打开手动存档菜单，明确选择 `slot_1`、`slot_2` 或 `slot_3` 后才会写入；
- L：打开读档菜单，选择已有手动格后还需点击“确认读取”才会恢复日期、时刻、体力、玩家位置及世界状态；
- 每 120 秒自动轮换写入 `auto_1`、`auto_2`、`auto_3`；自动槽不会覆盖手动槽；
- 每个文件包含 `save_schema_version` 与 `timeline_kind: normal`；手动格和自动格全部彼此独立；
- 写入先落到临时文件，保留同一格的上一个主文件为备份；主文件损坏时自动读取备份。

## 保存的数据与边界

当前保存纯数据：Game Session 快照（含世界种子）、背包快照、个人料理笔记、当前区域、玩家像素位置、农田状态、鸡舍当日照料/连续照料/逐枚待收鸡蛋品质、采集点已采集日期和钓鱼点当日次数。当前天气、预报和野外来源奖励由日期与种子稳定推导；它不保存 Godot 节点、场景路径、UI、动画、输入状态或正在编辑的料理组合。

普通时间线的实际存档根目录是 `user://saves/normal`。开发环境的启动与测试脚本会将 `user://` 重定向到 D 盘 Godot profile；未来灾变时间线必须使用不同根目录与不同 `timeline_kind`，不能复用或覆盖这里的文件。

`TimelineSaveRepository` 现在接受可选的 `timeline_kind` 参数。普通时间线仍使用默认值 `normal`；灾变适配器必须使用独立根目录（例如 `user://saves/apocalypse`）和 `apocalypse` 标识。加载时会同时校验根目录中的文件结构与请求的时间线类型，防止两种时间线互相读取。

## 恢复策略

读取顺序为主文件、备份文件。JSON 解析、schema 版本、时间线类型和快照存在性任一不满足时，主文件会被拒绝；备份有效时会恢复并在 HUD 给出说明。

Game Session 快照目前从版本 1 升至版本 2；旧版本没有世界种子时会采用普通规则中的默认种子补全天气，不会因本次升级变成不可读取的死档。
料理笔记独立使用版本 2 快照并兼容版本 1；旧档没有 `cooking` 字段时以空笔记恢复。旧档没有采集/钓鱼字段时，各点位按当天尚未使用恢复；没有 `chicken_coops` 字段时，鸡舍从当前日期的未喂食、未抚摸、零连续照料且无待收鸡蛋状态开始，不追补旧日期产物。
JSON 读回后的整数型数值会先经过合法性检查，再规范化回运行时整数；这保证料理笔记等严格快照不会因 JSON 数字表示差异而拒绝整份 HomeRegion 存档。

## 验收

- K 后明确选择一个手动格；移动、等待时间推进，再按 L 选择该格并确认，玩家位置与时钟恢复；
- 三个手动格可保存不同进度，任一格被覆盖后仍保留该格上一个版本的备份；
- 空格不能读取，选择读档格不会立即改变世界，只有确认读取才会回档；
- 重复存档一次后，破坏主 JSON，加载仍恢复上次有效备份；
- 自动槽与手动槽文件分离；
- 存档测试只使用独立测试根目录，不影响真实存档。
- 自动化回归覆盖：保存第 1 日状态，连续睡眠至第 3 日，释放旧 HomeRegion、实例化新 HomeRegion 后读档，并检查农田、鸡舍、采集、钓鱼、料理笔记、背包和玩家位置。
