# Project X 游戏设计总纲

## 1. 产品定义

Project X 是一款单人、离线、2D 像素风生活模拟游戏。玩家继承祖父留下的旧家园，在一个会随年份、经济、关系和事件变化的开放小镇中安排每日生活。玩家可以种植、养殖、采集、钓鱼、料理、买卖、经营和建立关系，但不会被固定职业禁止进行其他活动。

核心体验是：

> 获取食材 → 使用厨具自由料理或直接交易 → 自用、送礼或经营 → 改善生活、关系与事业 → 解锁新的生产和经营选择。

游戏不要求玩家完成统一的线性主线。祖父留下的是选择生活的机会，而不是必须复兴农场的遗愿。

## 2. 设计支柱

### 2.1 玩家创造自己的生活故事

- 没有强制主线终点。
- 多条人物、事业和小镇故事可独立推进。
- 达成人生里程碑后仍可继续长期生活。
- 普通模式中的失败产生代价，但不会永久结束游戏。

### 2.2 行动自由，事业有取舍

- 玩家始终可以进行所有日常行动。
- 同一时期只能激活一个主要事业。
- 主要事业决定专业点、高阶许可、行业事件和效率加成。
- 转型会损失经营势能并造成旧技能生疏，但不会清空知识与历史。
- 家园土地有限；扩建餐厅或商店会实际占用农田或其他经营空间。

### 2.3 料理连接所有核心系统

- 农业、养殖、采集、钓鱼和采购提供食材。
- 自由料理产生自用恢复、NPC 反馈、委托商品和经营商品。
- 食材品质、新鲜度、风味、料理角色、厨具与角色技能共同影响结果。
- 玩家知识通过料理笔记累积，而不是依赖全知菜谱列表。

### 2.4 小镇会变化，但必须可读、可恢复

- 天气、季节、节日、供给和玩家销售影响需求与价格。
- 商家可以升级、衰退或停业。
- 关键功能始终存在修复或替代路径，避免存档软锁。
- NPC 采用可预测基础日程，并根据世界状态、关系和事件调整。

### 2.5 普通生活与末日生存严格分离

- 普通模式保持温暖、治愈和宽松管理。
- 末日模式由主页、新游戏选项或主动隐藏剧情启用。
- 从普通存档触发末日内容时自动创建灾变时间线，保留普通时间线。
- 饥饿、口渴、卫生、工具耐久、感染和永久死亡只在末日模式考虑。

## 3. 目标平台与技术方向

- 首要平台：Windows PC。
- 后续平台：Android；不影响当前 PC 原型设计。
- 引擎：Godot 4 稳定版。
- 语言：GDScript。
- 运行方式：单人、离线、本地存档。
- 操作：键鼠与通用手柄，支持重映射。
- 首版语言：简体中文；所有文本使用本地化键。

## 4. 世界与美术方向

### 4.1 世界基调

- 架空的千禧年前后小镇。
- 具有电视、固定电话、收音机和基础电器，但起始阶段没有智能手机社会。
- 存在低度幻想、民俗和无法完全解释的自然奇迹。
- 外部技术按年份出现；小镇何时采纳以及如何采纳由经济、居民与玩家选择影响。
- 居民以设计好的阶段事件成长，不进行随机寿命和死亡模拟。

### 4.2 地图

- 手工设计的区域地图，不追求无缝大世界。
- 所有区域共享统一世界时间、天气、NPC 状态和事件状态。
- 玩家家园采用自由网格布置与模板建筑升级。
- 不提供《模拟人生》式自由画墙建房。

### 4.3 像素规范

- 内部分辨率：480×270。
- 显示比例：16:9，整数倍缩放。
- 场景基础网格：16×16 像素。
- 角色建议尺寸：16×32 或 24×32 像素。
- 四方向角色动画。
- 角色连续移动，工具、农田、家具和建筑按网格交互。
- 深度参考《矿石镇》的温暖色彩、比例和高可读性，但不复制或导入其贴图。

## 5. 普通模式核心系统

### 5.1 时间与体力

- 正式规则为春、夏、秋、冬各 28 天。
- 标准日长目标约为现实 18–22 分钟，最终通过试玩校准。
- 室内时间流速低于室外。
- 对话、背包、料理组合、家园布置和经营配置等决策界面暂停时间。
- 农作、伐木和其他体力劳动消耗体力。
- 进食、休息、泡澡或睡眠恢复体力。
- 普通走路、对话和菜单操作不消耗体力。
- 深夜和透支造成次日损失，但不直接没收金钱或物品。

### 5.2 家园与建筑

- 玩家继承祖父的住宅和有限土地。
- 土地可以布置农田、鸡舍、经营柜台、道路、装饰和后续经营建筑。
- 建筑采用预设模板与等级升级，位置可在允许的室外地块上选择。
- 混合经营被允许，但土地、资金、时间、雇员和许可形成真实取舍。
- 经营成长后通过自动化、帮工和供应合同减少旧职业的重复劳动。

### 5.3 农业与养殖

- 作物受季节、天气、品质和生长周期影响。
- 首版用 6 种春季作物验证快熟、多次收获、高价值、根茎、调味和甜味等角色。
- 首版动物仅包含鸡：购买、喂养、亲密度、产蛋和基础鸡舍升级。
- 普通模式工具不会损坏，只能永久升级。

### 5.4 采集与钓鱼

- 野外区域根据地点、时间和天气产生少量可采集物。
- 首版钓鱼采用单键“抛竿—等待—收竿”。
- 鱼种由地点、时间、天气和季节决定。
- 暂不制作采矿和战斗。

### 5.5 食材保鲜

- 易腐食材经历新鲜、普通、不新鲜、腐坏四个阶段。
- 腐坏食材不能制作正常料理，但可以堆肥或进入特殊用途。
- 冰箱、地窖和后续加工延长保存期。
- 谷物、种子和调味品等耐储物品不使用快速腐坏规则。

## 6. 自由料理系统

### 6.1 输入结构

- 玩家选择厨具，不直接选择抽象烹饪方式。
- 首版厨具为菜刀案板、平底锅、汤锅和烤箱。
- 普通料理使用一件主厨具并允许可选预处理。
- 一次最多投入 4 类主食材；同类重复投入表示增加份量。
- 调味料使用独立槽位。
- 不使用精确克数或秒级火候。

### 6.2 结果结构

- 满足料理原型的组合产生生成料理。
- 特定组合发现手工设计的招牌料理。
- 结构缺失产生失败料理。
- 明显冲突或胡乱组合产生黑暗料理。
- 食材组合决定料理是否成立；角色技能决定品质稳定性、效率、份数和高级技法。
- 高等级不能把错误组合自动变成美食。

### 6.3 信息与学习

- 烹饪前不显示料理类型、风味预测或成功概率。
- 玩家通过常识、居民线索和既往实验进行判断。
- 料理笔记记录已经尝试的组合与结果。
- 历史组合可以快速装填，但仍消耗食材、体力和游戏时间。
- 玩家可以替换同类食材继续实验。

## 7. 居民、关系与家庭

### 7.1 NPC 生活

- 居民拥有基础日程，并根据天气、节日、关系、商家状态和事件进行条件替换。
- 对白由手工编写的模块化内容构成，不使用在线生成式 AI。
- 对白条件包含关系、时间、地点、季节、天气、近期事件和玩家经营行为。

### 7.2 料理偏好

- 每名居民可拥有固定最爱料理。
- 生成料理按居民偏好口味获得第二档评价。
- 居民可拥有固定讨厌料理。
- 偏好初始隐藏，通过对话、传闻、共同用餐、剧情和实际赠送发现。
- 人物笔记区分已确认、有线索和未知信息。

### 7.3 关系成长

- 关系来源包括交谈、帮助、共同经历、经营互动、守约和送礼。
- 重复赠送同类礼物收益递减。
- 日常对白选择只造成小幅变化；重大选择明确提示后才锁定长期方向。
- 普通冲突大多可以通过后续行动修复。

### 7.4 首版恋爱与未来多人家庭

- 首版玩家为男性，两名恋爱候选为女性；这是内容范围，不是底层永久规则。
- 首版做到相识、熟悉、暧昧和确认恋爱，不制作结婚和孩子。
- 玩家可以同时发展多段恋爱。
- 忠诚与背叛由明确的关系约定决定。
- 不是所有角色都必须接受多人关系。
- NPC 与 NPC 之间也存在信任、亲近、兼容和冲突。
- 多人婚姻、共同生活与孩子属于后续扩展。

## 8. 经济、经营与小镇发展

- 不模拟每个居民的完整钱包和消费历史。
- 价格受到季节、天气、事件、供给量和小镇状态影响。
- 连续大量出售同类商品会压低短期收购价格。
- 玩家开店后，定价、品质、库存、口碑和客流影响销量。
- 商家可以升级、衰退、缩短营业时间或停业。
- 所有关键功能必须存在恢复或替代路径。
- 首版只制作家园经营柜台，可选择商品零售或料理供应。
- 完整餐厅的座位、点单、上菜、员工和厨房动线后续实现。

## 9. 首个可玩版本

### 9.1 内容范围

- 春季 14 天。
- 约 5 个室外区域：家园、商业街/广场、住宅区、河边、林地。
- 玩家住宅、杂货店和少量 NPC 住宅。
- 晴、阴、雨三种天气及次日预报。
- 6 种作物、鸡、采集和简单钓鱼。
- 4 类厨具与自由料理。
- 经营柜台。
- 6–8 名具名 NPC、2 名恋爱候选。
- 1 个春日料理集市。

### 9.2 明确不做

- Android 适配
- 完整四季
- 采矿和战斗
- 加工机器
- 完整餐厅
- 婚姻、同居和孩子
- 完整多人家庭
- 破坏性自然灾害
- 末日模式实际内容
- 人物衰老和时代技术内容
- 公开 Mod API
- 完整角色捏人
- 正式商业发行流程

### 9.3 完成定义

原型只有同时满足以下条件才算完成：

1. 新游戏可以无阻断地连续游玩至第 14 天。
2. 生产、料理、关系与经营至少形成一条可重复正向循环。
3. 键鼠和手柄都能完成所有核心操作。
4. 手动存档、轮换自动存档、完全退出和重新读取后状态一致。
5. 不依赖编辑器手工修复数据才能继续游戏。
6. 核心规则拥有自动化测试，关键交互拥有实机验证记录。
7. 每个完成模块包含中文说明、已知限制和后续扩展接口。

## 10. 远期扩展边界

- Android 横屏触控适配。
- 四季、更多作物、动物、鱼类和地区。
- 完整餐厅、雇员、供应合同和加工产业。
- 婚姻、多人家庭、孩子成长和居民人生阶段。
- 小镇现代化和技术采纳分支。
- 自然灾害、防范和恢复。
- 主动启用的末日模式、灾变时间线和生存需求。
- 稳定数据结构之后再评估公开 Mod 支持。
