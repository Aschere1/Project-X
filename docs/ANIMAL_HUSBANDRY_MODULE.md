# 鸡舍与动物性食材来源模块

## 模块目标

用一个固定鸡舍和一只母鸡验证“每日照料 → 次日产品 → 长期品质提升 → 料理食材”的完整闭环。首版保持《牧场物语》式的温和反馈：忘记照料只会损失次日产出，不会造成疾病、死亡或永久失败。

## 当前玩法

- 室外固定鸡舍中有一只名为“小麦”的母鸡；新游戏自带 14 份鸡饲料，可覆盖 14 日原型验证。
- 靠近鸡舍出现选中提示，按 E 按上下文依次执行：收取待收鸡蛋 → 喂食 → 抚摸 → 查看状态。
- 喂食消耗 1 份鸡饲料、1 点体力和 5 分钟；抚摸与收蛋不消耗体力，但各推进 5 分钟。
- 当天喂食后，进入次日生成 1 枚鸡蛋；未喂食则不产蛋并重置连续照料天数，但鸡不会生病或死亡。
- 同一天同时喂食和抚摸计入连续细心照料：连续 3 天产银星蛋，连续 7 天产金星蛋，其余为普通品质。
- 未及时收取的鸡蛋会留在鸡舍，每枚品质独立保存并按生成顺序收取；背包满时不会丢失鸡蛋。
- 雨天小麦安全留在鸡舍中，不产生额外惩罚；状态文字会明确说明天气影响。

## 数据与扩展边界

- `ChickenDefinition` Resource 保存稳定动物 ID、显示名、产品物品 ID 和品质阈值；场景互动不写死动物名称。
- `ChickenCoop` 只保存运行时纯数据：当前跟踪日期、今日喂食/抚摸、连续照料天数和逐枚待收鸡蛋品质。
- 跨日由世界统一结算入口驱动，与农田成长共享同一日期边界；睡觉和午夜自然跨日使用相同规则。
- 鸡蛋沿用背包的普通/银星/金星品质分栈，可直接作为自由料理系统的品质输入。
- 旧档没有鸡舍字段时从读档当天的未照料空鸡舍开始，不凭空补发过去鸡蛋。

## 首版有意不做

不加入多只动物、繁殖、疾病、死亡、放牧寻路、动物购买、饲料商店或鸡舍升级。这些功能只有在固定鸡舍闭环验证值得保留后才扩展；基础商店模块完成前由初始 14 份饲料保证可测试性。

## 验收步骤

1. 靠近鸡舍连续按 E：先喂食，再抚摸，第三次显示当日状态。
2. 睡到次日后按 E 收到普通鸡蛋；背包显示鸡蛋品质并与其他品质分栈。
3. 连续完成 3 天和 7 天的喂食及抚摸，分别获得银星与金星鸡蛋。
4. 任一天不喂食，次日不产蛋且连续照料归零，但仍可继续恢复照料。
5. 留下多枚鸡蛋后存档、改变状态并读档，待收数量、每枚品质、当日照料和连续天数全部恢复。
6. 雨天查看状态，确认鸡安全待在鸡舍且不受惩罚。
