# Project X 技术架构草案

> 状态：Draft。该架构先定义模块、接口与数据所有权；当前工程基线为 Godot 4.7.1，后续用实际运行和测试验证，再将难以逆转的部分转为 accepted ADR。

## 1. 架构目标

技术架构必须同时支持：

- 单人开发时能够逐模块完成和验证。
- 14 个游戏日内大量跨日、跨区域状态保持一致。
- 作物、食材、料理、NPC 和事件可以通过数据持续扩展。
- UI、地图与正式美术更换时不重写核心规则。
- 普通时间线与未来灾变时间线可以共享定义但使用不同规则集。
- Windows PC 首版与未来 Android 使用同一核心模拟和存档格式。

## 2. 总体形状

```text
键鼠/手柄
    │
    ▼
Input Adapter ──► Game Session Interface ◄── Save Adapter
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
        Domain Commands        Domain Events
              │                     │
              ▼                     ▼
      Authoritative World      Presentation Adapters
          Simulation                  │
              │                       ▼
              ▼                Godot Scenes / UI
       Content Catalog
```

核心规则不能直接依赖具体场景节点。场景节点把玩家操作转换为命令，并把游戏会话产生的状态与事件表现为动画、声音、地图变化和界面反馈。

## 3. 核心模块

### 3.1 Game Session

**职责**：拥有当前时间线的权威运行状态，并向调用者提供尽可能小的统一接口。

预期接口能力：

- 创建新游戏。
- 接受一个领域命令并返回领域事件或失败原因。
- 推进游戏时间并结算跨分钟、跨小时和跨日规则。
- 提供只读状态或面向 UI 的查询结果。
- 捕获可保存快照。
- 从已验证快照恢复会话。

Game Session 是外部模块的主要 seam。表现层不应分别调用农场、背包、料理和关系内部实现，从而避免 UI 知道结算顺序和跨系统不变量。

### 3.2 Content Catalog

**职责**：提供静态、可扩展的游戏内容定义。

首版内容类型包括：

- 物品与食材定义
- 作物定义
- 动物定义
- 厨具定义
- 料理原型与招牌料理定义
- NPC 定义与日程模板
- 对白与本地化键
- 商店商品和市场规则
- 节日及事件定义

内容通过稳定 ID 引用。显示名称、图标、场景路径或文件名都不能充当存档身份。

### 3.3 Authoritative World Simulation

**职责**：在 Game Session 内部结算时间、生产、库存、料理、关系、市场和事件。

内部可以拆分为时间、物品、农业、料理、居民、关系、经济与事件子模块，但这些内部 seam 不直接暴露给 Godot 场景。跨系统结算由 Game Session 维护明确顺序。

首版建议的跨日顺序：

1. 完成当日未结算的经营与关系事件。
2. 结算食材新鲜度。
3. 结算作物生长与天气影响。
4. 结算动物状态与产出。
5. 更新市场需求与商店库存。
6. 生成次日 NPC 日程和区域活动。
7. 创建安全自动存档点。

该顺序在实现与试玩后才能最终接受。

### 3.4 Save Module

**职责**：把 Game Session 的纯数据快照安全写入本地文件，并验证、迁移和恢复旧版本。

接口应隐藏：

- 文件格式
- 临时文件和备份策略
- Windows 替换文件行为
- 存档槽路径
- schema 迁移链
- 校验与失败回退

最低要求：

- 每个存档包含明确 schema 版本。
- 保存稳定 ID、数值、枚举值和结构化状态，不保存节点引用。
- 手动存档与自动存档使用不同槽。
- 写入失败不能破坏最后一个有效存档。
- 读取时先迁移、再校验、最后恢复世界。

### 3.5 Presentation

**职责**：将权威状态转换为玩家可以看到、听到和操作的 Godot 场景。

包括：

- 角色移动与网格目标高亮
- 区域地图与碰撞
- NPC 当前可见位置与动画
- 作物、动物和家园设施表现
- HUD、背包、料理、人物笔记和经营界面
- 音频、粒子、镜头和输入反馈

表现层可以暂时预测移动或播放动画，但不能自行改变库存、金钱、关系或世界规则。

### 3.6 Input Adapter

**职责**：把键鼠、手柄以及未来触屏操作映射为相同的语义动作或领域命令。

游戏逻辑不读取具体键值。核心动作示例：

- 移动
- 互动
- 使用当前工具
- 打开主菜单
- 确认/取消
- 切换物品栏
- 快捷打开人物或料理笔记

### 3.7 Scene Router

**职责**：执行区域和室内场景切换，并在切换期间维持 Game Session 与玩家位置状态。

Scene Router 不拥有世界时间、NPC 关系、作物或库存。它只决定加载哪个表现场景，以及加载完成后把权威状态表现在哪里。

## 4. 状态所有权

| 状态 | 唯一所有者 | 表现层可以做什么 |
|------|------------|------------------|
| 游戏日期、时刻、天气 | Game Session | 显示时钟、光照和天气效果 |
| 玩家金钱、体力、背包 | Game Session | 显示、选择和发出使用请求 |
| 作物状态 | Game Session | 显示对应阶段与交互反馈 |
| 动物状态 | Game Session | 显示位置、动画和情绪反馈 |
| 料理结果与笔记 | Game Session | 组织输入、显示结果与历史 |
| NPC 关系和日程 | Game Session | 显示可见 NPC 及对白 |
| 玩家当前像素位置 | 当前区域表现 + 存档快照 | 驱动物理移动并在安全点同步 |
| 音效、粒子、镜头状态 | Presentation | 自行管理，不进入世界存档 |

## 5. 命令与事件

游戏会话通过少量语义命令接受玩家意图，例如：

- `UseTool`
- `PlantCrop`
- `HarvestCrop`
- `CookDish`
- `GiveGift`
- `ChooseDialogueOption`
- `ConfigureBusinessCounter`
- `BuyItem`
- `SellItem`
- `Sleep`

命令成功或失败都返回可解释结果。成功时可以产生领域事件，例如：

- 体力变化
- 物品增减
- 作物阶段变化
- 新料理发现
- NPC 反应
- 关系约定变化
- 市场价格变化
- 跨日完成

表现层监听领域事件生成动画和界面反馈，但不能用动画完成回调作为核心规则的唯一依据。

## 7. 测试策略

- 领域规则尽量通过 Game Session 或相应深模块的接口进行无画面测试。
- 时间、料理、价格、关系与存档迁移使用固定输入和确定性结果。
- 地图、输入焦点、动画和像素缩放使用 Godot 实机或截图验证。
- 保存测试必须完整退出进程、重新启动并读取，而不是只在内存中序列化往返。
- 每个模块的测试描述可观察行为，不依赖内部函数或节点路径。

Godot 测试插件或自建 headless runner 尚未决定，必须在安装并确认本机 Godot 版本后选择。

## 8. 当前开放问题

1. 自动化测试采用 GUT、GdUnit4 还是轻量自建 headless runner。
2. 静态内容主要使用 `.tres`、JSON/CSV，还是混合作者工作流。
3. Game Session 对 UI 的只读查询使用快照、View Model 还是专门查询方法。
4. 玩家位置在跨区域和自动存档时的精确同步规则。

这些问题在工程骨架阶段通过小型可运行验证决定，不在文档阶段凭偏好冻结。
# 当前已落地：Game Session

`src/domain/session/game_session.gd` 是不依赖场景树的纯领域对象。它负责普通模式的日期、时钟、体力、睡眠和版本化快照；不读取输入、不写文件、不实例化场景。`GameRules` 提供数据化的开局时刻和体力上限。`TimelineSaveRepository` 现已承担普通时间线的版本化 JSON、备份回退与独立自动槽；`SaveCoordinator` 仅把场景中的纯数据转换为该仓储的快照输入输出。
