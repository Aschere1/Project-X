# 自由料理模块（首个可玩切片）

## 核心价值

料理不是固定菜谱列表，而是玩家以**厨具 + 主食材（最多四份）+ 可选调味**组成的一次尝试。成功组合会产出料理；不成立的组合仍会产出失败料理或黑暗料理。这样既保留实验空间，也避免玩家因一次未知组合白白损失行动。

本模块建立了可扩展的料理闭环。品质、稀有度、口味偏好、餐厅售卖、NPC 送礼和个人料理笔记的快速复现，均建立在纯数据结果之上，而不是写入场景脚本。

## 当前行为

- 在室外“旧料理柜台”旁按 **E** 打开料理面板；面板打开时，世界时间与移动暂停。
- **C** 轮换四类厨具：案板、平底锅、汤锅、烤箱；**T** 轮换背包中所有可料理食材（包含香草调味）。
- **G** 把当前食材加入主食材；最多四份，且不会超出背包中持有的数量。**H** 会把当前香草类食材设为调味。
- **J** 烹饪，成功时消耗所选食材、3 点体力和 15 分钟；体力、食材或背包空间不足时不生成结果，也不会扣除食材或体力。**U** 清空本次组合，**E** 关闭面板。
- 当前首批判定：汤锅 + 至少两种主食材 -> 蔬菜汤；案板 + 调味 -> 香草沙拉；烤箱 + 胡萝卜或土豆 -> 烤根茎；其余三种以上主食材的失配组合 -> 黑暗料理；其他未成立组合 -> 失败料理。
- 每次结果会按“厨具、已排序主食材、调味、结果”写入个人笔记；相同组合不会重复记录。笔记会把食材 ID 规范化为纯字符串，保证内存快照与 JSON 存档具有相同结构。
- **N** 可以在任何正常探索状态打开个人料理笔记；也可在料理面板中按 **N** 打开，关闭后会回到原来的料理面板。使用面板按钮，或 **W/S** 浏览条目、**E** 一键装填、**N** 关闭。
- 一键装填只把已发现的厨具、主食材和调味复原到料理台，不消耗或生成物品；按 J 烹饪时才再次检查体力、背包和实际食材数量。

## 品质、稀有度与招牌料理

- 背包中的每一组物品都带有 `普通 / 银星 / 金星` 品质。不同品质的同一物品不会混栈；料理会优先消耗较低品质食材，并按实际消耗食材的平均品质生成成品品质。
- 目前罗勒为银星少见食材，野生香草为金星珍稀食材；品质会显示在背包、料理完成提示和料理笔记中，稀有度记录最高等级的参与食材。
- 首批招牌料理：**汤锅 + 芜菁 + 胡萝卜 + 罗勒 = 春野浓汤**；**烤箱 + 土豆 + 胡萝卜 + 野生香草 = 野香烤根茎**。它们是独立物品 ID，后续可直接给 NPC 偏好、餐厅菜单和市场系统引用。
- 普通料理、失败料理和黑暗料理仍按既有规则产生；招牌搭配在通用规则前优先判定。

## 存档与边界

个人笔记以版本 2 纯数据快照存入普通时间线，新增品质、稀有度和招牌标记；版本 1 笔记会迁移为普通品质、普通稀有度和非招牌条目。旧存档没有 `cooking` 字段时会以空笔记恢复，不会失效；不完整或类型不正确的笔记条目会被拒绝，防止损坏数据污染当前会话。临时正在编辑的组合不保存，避免存档写入半完成的交互状态。

背包快照已升级为版本 2，将每个物品栈的品质一并保存。版本 1 背包快照自动把既有物品迁移为普通品质，因此不会破坏已有普通时间线存档。

本模块故意未实现：作物收获时的随机/技能品质提升、NPC 口味、餐厅销量和经济定价。它们是下一阶段的内容层，不应改变 `CookingEngine.resolve(...)` 的无场景、纯数据接口。

## 验收

1. 站在料理柜台附近按 E，面板出现，游戏时钟暂停；离开面板后恢复。
2. 选择汤锅，加入任意两份可料理主食材，按 J 后得到“蔬菜汤”，体力减少 3、时间推进 15 分钟。
3. 选择案板，加入一份主食材并将香草设为调味，按 J 后得到“香草沙拉”。
4. 使用不成立的组合时仍得到失败料理或黑暗料理；食材不足、体力不足或背包满时组合保留且没有消耗。
5. 保存、退出并读回存档后，笔记条数保持；加载无 `cooking` 字段的旧快照仍可正常进入世界。
6. 按 N 打开笔记，选择已发现条目并点击“装填组合”（或按 E）；回到料理面板时，厨具、主食材和调味与笔记完全一致，但背包数量没有变化。
7. 以不同品质食材料理后，背包中的同一成品会按品质分栈；保存并读档后品质保持。旧版背包/笔记快照仍能恢复，且默认迁移为普通品质。
8. 用汤锅加入芜菁、胡萝卜并设罗勒调味，或用烤箱加入土豆、胡萝卜并设野生香草调味，均会得到对应的招牌料理。
