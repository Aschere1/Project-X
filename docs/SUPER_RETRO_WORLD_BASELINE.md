# Super Retro World 开发期视觉基线

## 决策

Project X 在个人开发期整套采用 `Super Retro World - Farming v1.0.3` 作为统一视觉基线。后续新增美术先匹配这一套的 16×16 世界网格、32×32 人物画布、像素密度、暗色轮廓和高对比配色；准备公开发布时再逐项原创替换。

官方来源：<https://store.godotengine.org/asset/gif/super-retro-world/>

许可证允许商业和非商业项目使用、修改以及随完成的项目发布，但禁止把素材作为独立文件、素材包、仓库内容或可提取资源再分发。运行素材因此只位于被 Git 忽略的 `assets/private/super_retro_world_farming/`。

## 固定导入规则

- 世界地格固定为 16×16。
- 人物和农具动作使用 32×32 画布；较大挥砍特效允许 48×48。
- 已单独导出的 `Sprites` 文件直接作为精灵使用，不再从总览图猜切割区域。
- 地形使用 TileSet/Terrain；人物、作物、动物、树木、建筑和道具使用独立 Sprite 或 SpriteFrames。
- 碰撞仍由 Project X 的脚底、树根、墙体底部和水域形状决定，不能直接照整张图片尺寸生成。
- 每次替换建筑、树或大型物件时，都要按新 PNG 的真实不透明底边重新测量碰撞、交互锚点和遮挡矩形；禁止只换纹理。
- 物品 ID、农田 ID、交互 ID 和存档不引用素材文件名或图集坐标。

## 当前适配校准

| 对象 | 新素材画布 | 物理/交互适配 |
|---|---:|---|
| 玩家 | 32×32 | 12×10 脚底碰撞保持不变；精灵向上偏移 8px，碰撞底边与脚底重合 |
| 家园农舍 | 75×48，整数放大 2× | 120×16 墙脚碰撞，底边停在可见建筑底部；家门交互锚点移到门外 `y=144` |
| 家园树木 | 32×39，放大 1.5× | 8×6 树根碰撞覆盖根部像素；树冠遮挡区在碰撞顶边结束 |

鸡舍、池塘、采集点、钓点和料理台目前仍属于“缺口或待迁移表现”，因此暂时保留与各自当前可见素材一致的判定；换成 Super Retro 扩展素材时必须逐项执行同一校准流程。

## 覆盖矩阵

| 模块 | 当前覆盖 | 结论 |
|---|---|---|
| 草地、泥地、道路、雪地、沙地、悬崖、水与瀑布 | 完整或基本完整 | 使用包内 TileSet 与 Terrain；旧示例为 `TileMap`，需迁移到 `TileMapLayer` |
| 树木、岩石、围栏、灯、箱子、桶与通用装饰 | 完整 | 可直接用独立精灵或 TileSet |
| 玩家与普通居民行走 | 完整 | 32 名四方向角色；当前玩家先使用农夫第二套 32×32 图集 |
| 锄地、浇水、铲土、镰刀 | 基本覆盖 | 镰刀画布独立；斧、锤、采集、搬运等动作仍需补充 |
| 作物 | 20 组 | 足够覆盖首版春季农业；需要建立作物 ID 到精灵文件的映射 |
| 普通住宅、商店、旅店、市场与室内结构 | 基本覆盖 | 可支持家园和首批小镇建筑；独立鸡舍、谷仓和加工房不足 |
| 野生动物与宠物 | 部分覆盖 | 有鸟、猫、兔、狐、鼠、企鹅；不是完整畜牧系统 |
| 鸡、牛、羊、猪、山羊等畜牧动物 | **未覆盖** | 保留当前临时鸡素材，后续按同画风自制或另找明确许可的同风格补充 |
| 鸡舍、谷仓、饲料槽、孵化器 | **未覆盖** | 后续按建筑墙体和屋顶模块扩展 |
| 料理食材与成品料理图标 | **未覆盖** | Phase 4 按同画风制作统一 16×16 或 32×32 图标 |
| 厨房专用设备、餐厅服务物件 | 少量通用锅和家具 | 料理台、厨具状态和餐厅陈列需要扩展 |
| 钓鱼角色动作、鱼类、鱼竿和水域反馈 | **未覆盖** | 钓鱼模块继续使用临时可读标记，后续自制扩展 |
| 居民头像、恋爱表情 | **未覆盖** | Phase 5 单独建立原创头像规范 |
| HUD、背包、时间、体力、商店与料理界面 | **未覆盖** | 现有 UI 暂留；以后按该包配色原创统一 |
| 玩家经营、职业专用内容 | **未覆盖** | Phase 6 按同画风扩展柜台、招牌和行业设备 |
| 末日模式角色、感染体、防御与废墟 | **未覆盖** | 最后阶段独立扩展，不提前混入普通模式 |

## 替换顺序

1. 玩家行走、家园住宅和树木。
2. 地形 TileSet、道路、水和农田。
3. 六种春季作物及农具动作。
4. 通用室内、商店和小镇建筑。
5. 对照本表逐项制作畜牧、料理、钓鱼、头像、UI、经营与末日缺口。

每次替换只修改表现 Adapter；如果某项素材不存在，就明确保留回退图并标记，不能从总图中猜一块近似内容冒充。
